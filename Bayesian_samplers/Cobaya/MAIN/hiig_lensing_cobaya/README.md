# HIIG + gravitational lensing likelihood for Cobaya/CLASS

This package adapts the existing `LSigmaHIIG` Cobaya likelihood to the
log-normal weak-lensing treatment used in Chávez et al. (2026,
arXiv:2607.14254), while retaining GEHR host-distance covariance support.

## Files

- `lsigma_hiig_lensing_likelihood.py`: custom Cobaya likelihood.
- `LCDM/cmb_hiig_bao.yaml`
- `LCDM/cmb_snia_bao_h0.yaml`
- `LCDM/cmb_hiig_snia_bao_h0.yaml`
- `CPL/cmb_hiig_bao.yaml`
- `CPL/cmb_snia_bao_h0.yaml`
- `CPL/cmb_hiig_snia_bao_h0.yaml`

The YAMLs use Planck 2018 low-l TT/EE + high-l Plik TTTEEE + Planck lensing,
DESI DR2 BAO, Pantheon+ without SH0ES, and (where requested) the exact
`H0=73.48 +/- 1.66 km/s/Mpc` Gaussian prior used by Tsiapi et al. (2021).
For Planck efficiency they sample CLASS `theta_s_100` and save `H0` as a
CLASS-derived parameter, matching the acoustic-scale parameterization used in
standard CMB analyses.

## Lensing prescription

For each HIIG source:

    t = ln(M) ~ N(U,S^2)
    sigma_eff(z) = 0.088 z
    S^2 = ln[1 + sigma_eff(z)^2]
    U = -S^2/2

so `<M>=1`. The residual at fixed magnification is

    R_unlensed = R + (2.5/ln10) t.

Two numerical modes are available:

- `lensing_method: gh`: direct Gauss-Hermite marginalization. With
  `gh_order: 20` and `include_logdet: false`, this is the closest validation
  configuration to `five_par_lensing_test.py`.
- `lensing_method: analytic`: exact Gaussian convolution after the change
  `t=ln(M)`. This is recommended for production Planck+DESI+SN chains.

For the normalized likelihood the exact marginalized result is

    V_eff = V + b^2 S^2
    R_eff = R + b U
    ln L = -1/2 [R_eff^2/V_eff + ln(2*pi*V_eff)]

with `b=2.5/ln(10)`.

## Important validation sequence

1. Copy `lsigma_hiig_lensing_likelihood.py` to
   `/home/holman/HIIGalaxies/Bayesian_samplers/Cobaya/MAIN/` or change
   `python_path` in each YAML.
2. Make sure `Compilation2026_main.csv` and `GEHR_base.csv` are either in that
   directory/current working directory, or replace them by absolute paths.
3. First reproduce the old MultiNest likelihood with:

       lensing_method: gh
       gh_order: 20
       include_logdet: false
       correlate_host_mu: false   # only if the old run treated rows independently

4. Once the numerical comparison is understood, use the production settings:

       lensing_method: analytic
       include_logdet: true
       correlate_host_mu: true

5. Test configuration before launching an MCMC:

       cobaya-run LCDM/cmb_hiig_bao.yaml --test

6. Then run, for example:

       mpirun -np 8 cobaya-run CPL/cmb_hiig_snia_bao_h0.yaml

## Data/systematics notes

- `zmax: 14.0` applies only to HIIG; GEHR anchors are retained independently.
- Lensing is never applied to GEHR anchors.
- `sigma_sys_mag` adds the same extra systematic magnitude uncertainty to all
  L-sigma objects. Alternatively, `sigma_sys_column` can point to an input CSV
  column containing an object-by-object systematic uncertainty in magnitudes.
- `sigma_v_pec_kms` adds a peculiar-velocity contribution to HIIG redshift
  uncertainty.
- Malmquist/selection corrections are not generated by this likelihood. If the
  sample requires such corrections, they should be applied to the data or
  supplied through an explicitly modelled nuisance term.
- The `0.088 z` prescription is deliberately kept identical to the 2026 paper.
  At the highest redshifts it is an extrapolated phenomenological model and
  should be included in robustness/systematics tests.

## About likelihood normalization

The old MultiNest code used an unnormalized Gaussian core in the successful
lensing reproduction. Because the L-sigma variance depends on sampled
`beta_ls` (and on `sigma_int` if it is freed), dropping the normalization is
not generally parameter-independent. The production YAMLs therefore use
`include_logdet: true`. To reproduce a previous chain rather than perform the
preferred production inference, set it to `false`.
